# Complete training recipe

The top-level README gives the executable sequence. This document records its
settings and outputs. No checkpoint, carrier, cached input, or research file
from a previous run is an input to this recipe.

## Preparation

`fec1 prepare --data DATA --run RUN --workers N` runs these stages in order:

| Stage | Operation | Main output under RUN |
| --- | --- | --- |
| cache | All-frame raw DIII-D preprocessing, input fixes and content hashes | `cache/` |
| pca | Train-only initial PCA64, up to 60,000 sampled frames | `artifacts/source_pca.joblib` |
| source | Five-fold shot-OOF source rows at stride 4 | `artifacts/source_rows.npz` |
| inputs | Spatial input arrays in exactly that row order | `artifacts/inputs/` |
| targets | Normalized flux targets and PCA decoder cache | `artifacts/target_normalized.npy`, `pca_basis.npz` |
| topology | Exact scorer-derived topology on train shots at stride 4 | `artifacts/topology.npz` |
| contours | 64 polar angles and 128 contour points | `artifacts/contours.npz` |

The original ordered manifest gives 316,200 training rows. The initial PCA is
only a source-row preparation dependency; every deployed carrier fits its own
PCA without outer-shot targets. Three nested source forests have 96 trees,
leaf sizes 4/2/4 and max_features .7. The source seed is 260901; the initial PCA
uses random_state 260902. Exact settings are recorded in each stage's command.

## Fitting all five folds

`fec1 train --run RUN --device cuda --workers N` performs four stages per fold:

1. Fit a carrier with five outer folds, three inner folds, seed 260905, PCA64
   and three 96-tree ExtraTrees regressors. Each correction-training row has an
   out-of-shot base prediction. Outer shots never enter that fold's base fits.
2. Fit the pooled DCT scalar-reference network from random initialization.
   Its defaults are width 384, 24 channels, 36 epochs, batch 128, AdamW learning
   rate .0002, weight decay .0001 and legacy geometry loss weight .003.
3. Expand fitting to include formerly unused inner selection shots, retaining
   64 fixed selection identities and preserving outer identities. Freeze the
   scalar predictor produced by step 2.
4. Fit a fresh spatial-attention DCT24 field model with width 384, symmetric
   geometry loss .003, warmup 4, exact selection every 6 epochs and patience 3.
   Batch size is 128; the seed is 260905 plus fold. Inner selection chooses
   the epoch and calibration. The scalar predictor stays frozen.

Each member uses 696 contextual features and 192 spatial tokens (five values
plus R/Z). It predicts coordinates and 575 nonconstant 24x24 DCT coefficients
on a 65x65 grid. The carrier supplies the base field and scalars. At export,
saved per-fold shape/coordinate strengths and the frozen scalar predictor are
applied before averaging five calibrated predictions with weights .2 each.
All-frame inference uses four interleaved stride-4 sequences for the contextual
difference and whole-sequence mean. Those details are shared with evaluation.

The historical selected epochs were 36/30/30/36/36. A fresh run selects and
records its own epochs; the workflow does not force those historical choices.
The optional low-level frozen-calibration path applies calibration before all
supervised field losses and geometry losses, once per term. Default historical
retraining selects calibration internally and leaves that option unset.

The completed run contains `model.json` with SHA-256/size identities for:

```text
artifacts/base_fold0/base.joblib ... base_fold4/base.joblib
artifacts/dct_fold0/checkpoint.pt ... dct_fold4/checkpoint.pt
```

These files are generated by training. No old model is imported. The five
full carriers are large because the PCA-output forest stores 64-dimensional
values at its tree nodes. Historical deployment files total 36.9 GB; rebuilding
produces similarly large files. Training checkpoints and carriers are written
without compression. Other numeric caches and prediction archives use their
normal NumPy archive encoding.

## Local metrics and prediction

`fec1 evaluate` verifies the trained artifacts, pools each outer-fold training
prediction exactly once, fixes the five-member ensemble and evaluates all
689 development shots. `RUN/evaluation/result.json` contains `pooled_oof_score`
and `development_score`, with S, R2_psi, R2_qb, D_LCFS and consistency. It also
writes development predictions aligned by shot and frame. Frozen audit remains
excluded. The run profile distinguishes real-data results from synthetic checks.

`fec1 score` independently rescores that complete development archive. It
verifies cached content, shot identities, every frame, array shapes and finite
float32 values before opening target arrays. It rejects train/audit identities
and partial development archives. It does not score unlabelled public inputs.

`fec1 predict --run RUN` verifies the ten generated artifacts before loading
and writes the public archive plus `predictions.json`, containing input content
hashes and the shot order. Input caches require matching raw content, config
and implementation identities. Use a new output directory for each prediction.
The `compare` utility checks numerical parity of complete three-output shots;
its bounded comparison accepts only the first N shots starting at zero.

## Resume and independent runs

`RUN/run.json` records the source/config fingerprint, raw-data fingerprints,
exact split hash, environment, commands, logs and stage outcomes. Separate run
directories are independent; the workflow uses no global generated cache.
Only one preparation/training/evaluation process can hold a run's lock.

Use `--resume` on prepare/train/evaluate after interruption. Completed stages
are skipped if their outputs exist. Before retrying a failed stage, partial
outputs move under `RUN/failed/` and attempt logs remain under `RUN/logs/`.
A failed neural fit restarts that stage from scratch; it does not resume the
optimizer mid-epoch. Preserve the code, config and raw data for a continuing run.
Model hashes are checked before evaluation/prediction. Intermediate arrays are
not rehashed on every resumed stage; keep them intact or start a fresh run.

Use a fresh run for deliberate changes. This repository rebuilds the historical
method and reports measurements; it does not promote a research incumbent or
require the original project's external pilot/confirmation protocols. No score
improvement or exact weight identity is asserted for a new training run.

## Running on a cluster

Preparation can run in a CPU allocation with ample RAM and disk. Run training
in an appropriate GPU allocation. `scripts/train.sbatch` is an example with
96 GiB RAM and one GPU; supply your cluster's account, partition and time limit
when submitting. Set an absolute Python executable and run directory, and pin
the reviewed Git commit. Create `logs/` before submission because Slurm opens
its output before the shell starts. Git metadata and the checkout must be
reachable on the compute node. The script verifies source and a clean pinned
commit before and after execution.

```bash
mkdir -p logs
export FEC1_PYTHON="$PWD/.venv/bin/python"
export FEC1_RUN_DIR="$PWD/runs/main"
export FEC1_REVIEWED_COMMIT="$(git rev-parse HEAD)"
sbatch --account=YOUR_ACCOUNT --partition=YOUR_GPU_PARTITION scripts/train.sbatch
```

If running a downloaded archive without Git, use the ordinary CLI from your
own compute allocation. The standalone commands record content identities and
do not need Git metadata.
